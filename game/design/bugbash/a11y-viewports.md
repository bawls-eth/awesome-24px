# Accessibility and viewport sweep (lane a11y, branch bb-a11y)

Test: `game/tests/a11y-viewport-sweep.test.js` (browser/full, blockDb, Town via the OFFLINE stub only). 16 page views x 7 viewports
(320x568, 360x640, 390x844, 414x896, 667x375, 768x1024, 1920x1080) plus 5 preference passes per page at 390x844 (OS reduced motion,
mm-reduce-motion + flashes:false, hudScale 1.5 = "150%", browser zoom 2 = "200%" (no 200% pref exists, so this is a reflow check), mm-high-contrast).
Allow-list: `game/tests/fixtures/a11y-allow.json` (key `page|check|selector`). It may only shrink: new offenders fail, and an entry that no longer
occurs also fails (delete it or run `A11Y_PRUNE=1`). `A11Y_SEED=1` regenerates it, `A11Y_REPORT=1` rewrites the tables below. Full run about 9 minutes.

What passed everywhere (zero offenders): no console errors, no horizontal scroll except one (bugs at 320), every tap target >= 44 px (the 8-bit CSS holds),
every icon-only control has an accessible name, every focusable shows a focus indicator, Menu button visible and not overlapping at all 7 viewports
(Town's Menu is `#where-to-btn`). Contrast is computed from computed styles (ancestor background compositing, opacity); gradient/image backgrounds and canvas text are skipped, so they are not covered.

Heuristic caveats: `keyboard-primary` matches the first Tab stop whose name fits a per-page regex (shared chrome excluded). `no-effect` on pop/stack/stalk/echo
may be the heuristic (the result card or intro changes state outside the diff we watch); verify by hand before fixing. 

## Worst 15 (one page summary)

1. All lanes except echo: the `mm-high-contrast` pref is never applied on ANY page (`data-high-contrast` is never set on `<html>`): affects angler, bugs, dash, deepdelve, hub, isles, jam, lantern, pop, realm, stack, stalk, town. Owner: shared (mm-settings.apply is only used where settings mount), then each lane must load it. Fix: have mm-side-access / mm-settings.apply run on every page and add CSS for `[data-high-contrast]`.
2. realm (HUD ability slots): `#realm-ab-1..3 span.cd/.key/.nm` contrast 2.9-3.3:1 and `span.nm` is 10px (<12). Fix: text colour `#c2c3c7`+ on `#1d2b53`, min 12px.
3. town: `#walkie-talk-btn` 2.45:1 and `#bestie-label` 2.11:1 (grey on cream, 12px). Fix: darker ink (#5f574f gives 6:1).
4. isles: `#toast` 1.17:1 (text #1d1e29 on #0b0d1a, invisible when shown). Fix: colour `#fff1e8`.
5. lantern: `button.btn.testfall` 3.52:1 (red on navy) and `button.btn.retire` 4.02:1. Fix: `#fff1e8` text or `#ff77a8`.
6. jam: locked song hint `.card.locked small` 3.57:1 (#82779a on #2a2340). Fix: `#c2c3c7`.
7. realm: Realm pages ignore the "Huge" text size (x1.05-1.09 instead of x1.5); town, dash, pop, stack also ignore hudScale 1.5 (x1.00). Fix: honour `--ui-scale` on page fonts/HUD.
8. town: with 150%/200% text the Menu "Where to?" is covered by `#gate-pointer-close` / `#gate-pointer-text` / `#quick-chat-row > button`. Fix: stack the gate pointer below the Menu or hide it when scale > 1.
9. town + realm + isles + angler(h1 only) + hub-map: no `<main>`, no visible `<h1>`; canvas without aria-label (`#game-container > canvas`, `#realm-canvas`). Fix: add `<main>`, a visually-hidden h1, `aria-label` on canvases.
10. realm-world: primary action "Play the Daily world" needs 12 Tab presses, hub-map needs 16 (the map card list comes first). Fix: tab order or a skip link / put the primary first.
11. realm-dungeon: no focusable control at all before the game starts (keyboard-only players get zero stops). Fix: tabindex on the canvas wrapper plus a visible start/pause control.
12. angler, bugs, isles (maybe), pop, stack, stalk, echo: keyboard-primary not found or no effect (see caveat); the angler and bugs first screens expose no Cast/Play button reachable by Tab.
13. town: counters `#wood-count`, `#bug-count`, `#fish-count`, ... `#museum-cap` are 11px at 667x375 (12 elements). Fix: min 12px in the landscape media query.
14. bugs (festival): horizontal scroll at 320x568 (scrollWidth 333). Fix: find the 333px child (likely the meadow card row) and allow wrapping.
15. reduced motion: town, realm-world, realm-dungeon do not set `data-reduce-motion`/`html.reduce-motion` from `mm-reduce-motion` / `flashes:false`. Fix: call MMSettings.apply on boot.

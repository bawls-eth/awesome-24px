## 3. Findings for other lanes
- **D4, P2, b03-r2-05:** still open, see the table. Replay file `game/tests/r4-open/b03-r2-05-pad.replay.js` is red on d08838a
  (390x844: 6.4% of the room hidden; 360x640: 9.1%). Move it to `game/tests/beta-r4-dungeon-pad.test.js` and register it with the fix.
- **D3, test stability, beta-s07-town-cull check [3]:** red once on the tip under load (load/core ~1.2), message
  `after moving to 900,1500 nothing in view is culled Star:@930,1651 Star:@972,1427`. Cause (traced): the firefly sparkle pool
  (`main.js` ~6408 `ffSparkles`, shown / moved at ~6619) parks hidden stars far away, where the cull pass (every 4th frame, `main.js` 2061)
  excludes them; when one is shown near the hero it stays excluded until the next pass. At 60 fps that is <= 67 ms; at the ~10 fps of a
  loaded test box it is 400 ms, exactly the test's sample delay. Player impact: a sparkle appears up to 4 frames late (cosmetic).
  Suggested one-line fix in `cullOffscreen`: never exclude an object whose `visible` is false (clear the bit and `continue`): hidden
  objects cost nothing to render, and a pooled object is then drawn on the very frame it is shown. The check does not need changing.
  The same pattern applies to `sparkleStar` / `sparkleGlow` (main.js 2002).
- **All, hygiene:** `beta-s03-backup-skip.test.js` passes 25/25 against the pre-fix tree because it loads `shared/mm-backup.js` from
  the test's own checkout, not from the server: it cannot show red-before with a served old tree. Not a bug; the new UI replay covers it.

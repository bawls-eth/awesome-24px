# Beta b14: multiplayer, netcode, saves, backup (2026-11-23, 05:26-06:15 UTC)

All runs were offline. Every context used `blockDb` (0 DB requests and 0 sockets in every run). For the Town I used the in-page FAKE Firebase SDK from `net-hostile-presence.test.js` or "Play offline". I did not use live presence because it was not needed: every multiplayer path I tested runs through the real net.js and main.js code with synthetic remote players. No chat was sent and nothing was written to the database.

## Coverage
- **Presence (fake SDK, 1280x720):** 100 synthetic players, the 60-sprite cap, refilling after 30 drawn players leave, 300 add/remove churn on one id, change-only records past the cap, and removing everyone. Hostile but valid names: own-name duplicate, fullwidth, Zalgo, RLO, ZWJ emoji, zero-width, "[Server]" and Arabic. The cap worked, slots refilled correctly, and the churn leaked no objects (scene objects went 951 -> 1131 -> 951). There were 0 errors.
- **Realm invites and walkie (fake SDK, 390x844 touch):** I sent invites from a stranger, from a player in town (duel), a second invite (2v2) while one was showing, an accept with no party record, and a day-old invite. For walkie I sent memos from a stranger and from my bestie.
- **Co-op `?party=local` (two tabs, same seed):** Seats 0 and 1 each saw one partner ghost and the "🤝 Hero 1 · 36t" tag. When B closed, A dropped its ghost within 3.5 s. I also compared the shared save state.
- **Saves:** I tested two Town tabs; a Lantern Backup and Restore round trip onto a fresh "new device" context, using the old-format fixtures from `save-compat-fixtures.js` (34 keys, 0 leaves changed, so that path works); a backup containing one corrupt key; a restore onto nearly full storage; a Restore while a Town tab was open; the Town's own Backup and Restore buttons; and a scan of backup coverage against SAVE-KEYS.md.

## Top findings
1. **b14-03 P0:** The Town's "📂 Restore" accepts the Lantern's full backup file and stores `{format, v, keys}` as the town save. This wipes the name, resources, museum, achievements and realm, and the join screen comes back. `importSave` accepts any JSON object.
2. **b14-01 P0:** With two Town tabs open, the last writer wins for `resources`, `lifetimeStats` and `achievementsUnlocked`. I proved it: 5 wood from tab A were gone after tab B picked 2 fruit. There is no warning about another open tab and no storage listener.
3. **b14-02 P0:** A Lantern Restore is silently undone by a Town tab that is still open. One fish caught there reset the restored wood 12 / stone 7 to 0 and emptied the achievements and stats.
4. **b14-04 P1:** A backup with one corrupt minor key (the daily gift) cannot be restored at all ("nothing was changed"). Export still says "saved, keep it safe", so the player finds out only on the new device.
5. **b14-05 P2:** There are two Backup systems. The Town "💾 Backup" exports only the town save. The full backup exists only inside the Mad Maze Lantern.
6. **b14-06 P2:** Same-device co-op: both seats write the whole `pixeltown-realm-v1`. Seat 0's position was proven lost. Chests, quests and events are at risk by the same code path.
7. **b14-07 / b14-08 P3:** Name hygiene. Zero-width characters are kept, duplicate and "[Server]" names are allowed, and the 16-character cut splits ZWJ emoji even though the net.js comment says it never does.
8. **b14-09 P3:** Wide names overflow under the bestie heart in the player list, and an RTL name flips the score to the left.
9. **b14-11 P3:** A second Realm invite that arrives while one is showing is deleted and never shown.
10. **b14-12 P3:** Walkie memos from non-besties are ignored but stay in the database. **b14-13 P3:** Settings, including accessibility ones, are not part of the backup.

## What felt great
- The presence cap and slot refill are solid, and the hostile-name rendering is safe. All remote text reaches the page as plain text.
- Invite gating works: strangers' invites are rejected, as are day-old invites and path-like party ids.
- The Lantern Restore flow is good. It validates first, shows a clear list, confirms, rolls back on a failed write, and round-trips old saves with zero field loss.
- Co-op ghosts join and leave cleanly.

- **Live presence:** not needed, so I did not join.

- **Private mode:** already covered by the save-compat-pages SecurityError run.
- **Cross-game medals after playing every game:** no time. The machine load (load average about 25) made each browser script take 3 to 5 minutes.
- **b14-06 for chests and quests:** proven only by code reading. A fog/discovery rerun (s7) did not finish before the deadline.

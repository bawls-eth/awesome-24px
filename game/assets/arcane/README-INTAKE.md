# Arcane art intake (automatic hand-off to the admin)

The owner produces hero/creature/item art in ChatGPT and sends each batch ZIP (B2, B3, ...) to the manager session.
The manager runs `game/tools/ingest-art-zip.py`, which validates the batch (sizes, alpha, 4x4 pixel grid, palette,
margins, empty/duplicate frames, standing heights), files it under `game/assets/arcane/<batch>-<label>/`
with a `validation-report.json`, updates `INDEX.json`, commits and pushes to the dev branch, then pings the admin.

## What the admin does with a new batch (every session, no waiting for anyone)
1. `game/assets/arcane/INDEX.json` is the list of batches. `MMArt` must load EVERY batch listed there (read the
   index, then each batch's `manifest.json`); never hard-code batch folders. New classes/creatures appear in the game
   automatically by manifest id; if MMArt does not read INDEX.json yet, make that your next art slice.
2. Read each new batch's `validation-report.json`. `status: provisional` = usable now; `needs-fix` = usable
   but listed problems should be repaired in code (see below) or reported back to the manager for a ChatGPT redo.
3. Wire the new heroes (hero select, Lantern cards, arena draw, unlocks) and add them to `art-integration.test.js`
   (all manifest paths load, frame counts match, animation plays, no console errors).
4. Fix in CODE (never by spending image credits): halo or edge-colour cleanup, palette consolidation across batches
   (keep the approved B0 art untouched; write consolidated copies if needed), per-view display scale for small
   standing-height differences (use the `standing_heights` in the report), muzzle calibration.
5. Update `design/STATUS.md` and the daily report with which classes/creatures now have real art.
6. If the same asset also exists from the admin's own OpenAI generation and from a ChatGPT batch, the ChatGPT batch
   wins unless it has a blocking problem.
